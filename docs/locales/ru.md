> Менеджер прямой потоковой загрузки в облако — передача файлов по URL напрямую в персональное облачное хранилище без сохранения на локальный диск и без расхода домашнего интернет-трафика.

## 🛡️ Обзор проекта и ключевые возможности

<details open>
<summary><b>🛡️ Обзор проекта и ключевые возможности</b></summary>
<br>

`remote-dl` — это персональный менеджер загрузок для операторов, которым требуется сохранять объемные файлы (видео высокого разрешения, архивы, датасеты, исследовательские массивы данных) **напрямую в собственное облачное хранилище** без предварительного скачивания на локальный компьютер.

Компактный нативный CLI-клиент (`rdl.exe`) для Windows взаимодействует с легковесным бессерверным (Serverless) бэкендом. Фактическая передача байтов осуществляется полностью внутри облачной инфраструктуры, благодаря чему локальный накопитель и домашнее интернет-соединение оператора полностью исключены из цепочки передачи данных.

Инструмент рассчитан на **индивидуальное изолированное использование (self-hosted)**. Вы подключаете собственный аккаунт облачного хранилища; данные и ресурсы никогда не передаются сторонним пользователям.

</details>

## ⚡ Основные функции

<details open>
<summary><b>⚡ Основные функции</b></summary>
<br>

- **Потоковая передача с нулевым расходом диска** — файлы любого объема передаются через сквозной потоковый конвейер; промежуточная запись на диск не производится ни на клиенте, ни на сервере.
- **Нативная интеграция с OneDrive** — загрузка файлов фрагментами (чанками) с автоматическим возобновлением при сбоях через Microsoft Graph API.
- **Надежная аутентификация одного пользователя** — одноразовые пароли (OTP) в связке с отзываемыми постоянными токенами; отсутствие сложных учетных записей и сторонних сервисов идентификации.
- **Единое управление через несколько интерфейсов** — нативный консольный клиент (CLI), адаптивный веб-интерфейс для мобильных устройств и приватный Telegram-бот работают с единым бэкендом.
- **Строгая изоляция границ доверия** — учетные данные никогда не покидают предназначенный для них уровень (оператор → Edge Worker → облачный раннер → облачный провайдер).
- **Автоматическая ротация токенов** — при каждой успешной загрузке токен обновления OAuth перезапрашивается и сохраняется в зашифрованном виде, что исключает потерю доступа даже после длительного простоя.

</details>

## 💻 Совместимость и поддерживаемые платформы

<details open>
<summary><b>💻 Совместимость и поддерживаемые платформы</b></summary>
<br>

| Параметр | Поддержка |
|---|---|
| Операционная система (клиент) | Windows 10 (сборка 1809+) и Windows 11 |
| Архитектура процессора | Только x86_64 |
| Набор инструментов Rust | 1.75+ (зафиксирован в стабильной ветке через `rust-toolchain.toml`) |
| Компоновщик (Linker) | MSVC (Visual Studio Build Tools 2022) |
| Облачное хранилище | Microsoft OneDrive (Personal или Business) через rclone |
| Клиент Telegram | Любой официальный или сторонний клиент с поддержкой Webhook-ботов |

Готовый бинарный файл клиента статически скомпонован со средой выполнения MSVC, поэтому у него нет внешних зависимостей от сторонних библиотек, кроме стандартных системных DLL Windows (`KERNEL32.DLL`, `USER32.DLL`, `ADVAPI32.DLL`, `CRYPT32.DLL`, `WS2_32.DLL`).

## 🔒 Безопасность и архитектурные инварианты

<details open>
<summary><b>🔒 Безопасность и архитектурные инварианты</b></summary>
<br>

- **Шифрование данных конфигурации (Token at rest)** — Токен доступа, сохраненный в `%APPDATA%\rdl\config.json`, защищен аппаратным шифрованием Windows DPAPI (`CryptProtectData`). Расшифровать его может только та учетная запись Windows, в которой он был создан.
- **Шифрование данных при передаче (Token in transit)** — Клиент `reqwest` собран с параметром `https_only=true`; токены передаются исключительно по защищенному каналу TLS в заголовке `Authorization` и никогда не попадают в параметры URL.
- **Минимальный периметр доступа** — Управление ботом разрешено только одному подтвержденному пользователю (`TG_OWNER_ID`); вебхуки требуют секретный ключ в пути URL, известный только Telegram.
- **Маскирование конфиденциальных данных в логах** — Любые передаваемые в GitHub Actions ссылки и имена файлов маскируются командой `::add-mask::`, что исключает их появление в открытых журналах сборки.
- **Самовосстанавливающаяся ротация токенов OAuth** — При каждом завершенном цикле загрузки токен обновления OneDrive ротируется и записывается обратно в секрет репозитория `RCLONE_CONF`, предотвращая устаревание доступа.
- **Полное отсутствие телеметрии** — Ни CLI-клиент, ни бэкенд не собирают и не отправляют аналитику или логи использования на внешние серверы.

</details>

## 🛠️ Матрица устранения неполадок

<details open>
<summary><b>🛠️ Матрица устранения неполадок</b></summary>
<br>

| Признак | Возможная причина | Способ решения |
|---|---|---|
| `worker URL not set` | Первый запуск на компьютере без предварительной настройки | Выполните `rdl config set worker https://<ваш-воркер>.workers.dev` |
| `not authenticated — run rdl auth login` | В локальном кэше отсутствует токен доступа | Сгенерируйте постоянный токен через Telegram-бота и введите `rdl auth login --token <токен>` |
| `server rejected credentials (401)` | Токен был отозван или срок его действия истек | Получите новый токен в Telegram-боте и авторизуйтесь повторно |
| `rdl status <id>` возвращает `not found` | Ошибка в идентификаторе задания или данные удалены | Выполните `rdl list`, чтобы увидеть актуальный список активных задач |
| Ошибка рабочего процесса на этапе OneDrive | Токен OneDrive стал недействительным из-за простоя (>90 дней) | На компьютере выполните `rclone config reconnect onedrive:` и обновите секрет `RCLONE_CONF` |
| Telegram-бот перестал отвечать на команды | Несовпадение секрета Webhook или сбой в коде воркера | Проверьте состояние: `https://api.telegram.org/bot<TOKEN>/getWebhookInfo`, изучите логи воркера |

</details>

## 📦 Установка и развертывание

<details open>
<summary><b>📦 Установка и развертывание</b></summary>
<br>

### Установка готового исполняемого файла (Windows x64)

1. Загрузите файл `rdl-x64.exe` со [страницы релизов](https://github.com/GHSFS/remote-dl/releases).
2. Поместите его в каталог, входящий в переменную среды `PATH` (например, `C:\Tools\`).
3. Проверьте работоспособность в терминале: `rdl --version`.

### Сборка из исходного кода

Требуется установленный компилятор Rust версии 1.75+ и набор инструментов сборки Visual Studio MSVC.

```bash
git clone https://github.com/GHSFS/remote-dl.git
cd remote-dl
cargo build --release
# Исполняемый файл: target/release/rdl.exe
```

</details>

## 🚀 Быстрый старт и справочник команд CLI

<details open>
<summary><b>🚀 Быстрый старт и справочник команд CLI</b></summary>
<br>

```bash
# 1. Настройка подключения клиента к вашему воркеру
rdl config set worker https://your-worker.example.workers.dev

# 2. Однократная аутентификация (получите постоянный токен в боте)
rdl auth login --token <permanent-token>

# 3. Отправка ссылки в очередь загрузки
rdl https://example.com/dataset.tar.zst

# 4. Просмотр списка задач и статуса
rdl list
rdl status <job-id>
```

### Подробное описание командной строки


## ⚙️ Конфигурация и развертывание бэкенда

<details open>
<summary><b>⚙️ Конфигурация и развертывание бэкенда</b></summary>
<br>

### Конфигурация клиента

Файл настроек сохраняется по пути `%APPDATA%\rdl\config.json`. Секретные данные зашифрованы с помощью Windows DPAPI для защиты от доступа других пользователей или вредоносных процессов.

| Параметр | Назначение |
|---|---|
| `worker` | Базовый URL развернутого Cloudflare Edge Worker |
| `token` | Постоянный токен аутентификации (защищен DPAPI) |
| `folder` | Папка по умолчанию для сохранения файлов в OneDrive |

### Настройка автоматизации бэкенда

Облачный конвейер функционирует на базе рабочих процессов GitHub Actions (см. [`download.yml`](./.github/workflows/download.yml) и [`download-hls.yml`](./.github/workflows/download-hls.yml)):

1. Настройте `rclone` для OneDrive на локальном ПК (`rclone config`) и добавьте весь текст сгенерированного файла `rclone.conf` в секрет репозитория с именем `RCLONE_CONF`.
2. Создайте GitHub Personal Access Token (PAT) с правами `repo` и `workflow` и сохраните его в секрет `GH_PAT` репозитория (необходим для автоматического обновления токенов).
3. Разверните Edge Worker на Cloudflare, настроенный на отправку событий `workflow_dispatch` в репозиторий, и подключите его на клиенте командой `rdl config set worker <URL-воркера>`.

</details>

## ❓ Часто задаваемые вопросы (FAQ)

<details open>
<summary><b>❓ Часто задаваемые вопросы (FAQ)</b></summary>
<br>

**В: В чем преимущество перед использованием локальных `wget`, `curl` или `aria2c`?**
О: При локальной загрузке весь массив данных (зачастую десятки или сотни гигабайт) проходит через канал домашнего интернета и создает нагрузку на накопитель ПК. `remote-dl` осуществляет передачу файла объемом 100 ГБ, расходуя ровно 0 байт на диске и 0 байт домашнего интернет-трафика.

**В: Могут ли несколько человек одновременно использовать один бэкенд?**
О: Нет, система намеренно спроектирована как персональный однопользовательский инструмент. Добавление многопользовательского режима существенно усложнило бы архитектуру квотами, разделением прав и защитой от злоупотреблений, что противоречит концепции максимальной простоты.

**В: Поддерживается ли докачка при обрыве соединения?**
О: Да. Передача данных в OneDrive разбивается на фрагменты и автоматически возобновляется в облаке. Загрузка из исходного URL выполняется в рамках одного потока; в случае обрыва источника задание можно перезапустить заново.

</details>
